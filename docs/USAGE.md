## 1. 指令区

### 1.1 安装

执行：

1. 备份原版 jar（复制为 `<版本>.jar.bak`）
2. 打补丁：

```powershell
java "-Dfarlands.wide=true" "-Dfarlands.continuity=true" "-Dfarlands.epoch=true" `
  -jar patcher-cli-1.0-SNAPSHOT.jar `
  --in <官方26.2.jar> --out <fork.jar>
```

3. 用 fork jar 替换版本目录下的同名 jar
4. 将 `farlands-g1-mod-1.0-SNAPSHOT.jar` 放入 `mods\`
5. 启动

### 1.2 传送

执行：

```
/realtp <x> <y> <z>
/realtp <targets> <x> <y> <z>
```

`<targets>` 为实体选择器（`@p`、`@e`、玩家名）。命令方块可用。
坐标一律按真实坐标解释。支持任意精度（`1e1000` 合法）。

### 1.3 跨越窗口

执行 `/realtp` 指向窗口外坐标即可。系统自动：

1. 归档当前纪元区块至 `world\<archive_dir>\`
2. 恢复目标纪元归档（若存在）
3. 重载并落在目标

### 1.4 回程

执行 `/realtp <旧原点坐标>`。归档自动恢复。

## 2. 参数区

配置文件：`world\farlands.properties`（自动生成）。编辑后重新进入世界。

> 逐项详解与预设组合见 [配置指南](CONFIG.md)。

| 参数 | 含义 | 可调范围 | 错误后果 | 为什么这样限制 |
|---|---|---|---|---|
| `epoch_x` / `epoch_z` | 世界原点（真实坐标） | 任意整数 | **已生成区块全部错位**（见红线 R1） | 无限制——但后果不可逆，系统无法检测 |
| `auto_relocate` | 走路到窗口边缘自动重定位 | `true` / `false` | 非布尔值 → **JVM 中断** | 语义必须明确，静默降级会隐藏意图 |
| `relocate_margin` | 触发距离（格） | ≥ 0 | 负数 → **JVM 中断**；过大 → 重定位过晚（仍可用） | 负数无意义；过小会频繁重定位 |
| `relocate_discard_over` | 平移量超此值（chunk）改归档模式 | ≥ 1 | < 1 → **JVM 中断** | 平移量必须为正 |
| `fluid_tick_limit` | 每游戏 tick 流体 tick 上限 | ≥ 0（0 = 无限） | 负数 → **JVM 中断**；过大 → 异常地形下 CPU 持续满载（见红线 R4） | 0 是合法语义（关闭限流），负数是错误 |
| `archive_dir` | 纪元归档目录名 | 纯目录名 | 空/含 `/`、`\`、`..` → **JVM 中断** | 路径穿越会写到世界外 |
| `worldgen_sample_mode` | 远处采样策略 | `raw` / `clamp` / `quantize` | 非法值 → **JVM 中断**；`clamp`/`quantize` 改变地形（见红线 R5） | 模式必须明确，拼写错误不能静默变 raw |
| `worldgen_sample_clamp` | clamp 模式边界 | 正有限数 | 非正/非有限 → **JVM 中断**；过小 → 地形强重复 | 0 或 NaN 会使采样无意义 |
| `worldgen_far_threshold` | 策略生效距离（格） | ≥ 0（0 = 全域） | 负数 → **JVM 中断**；0 → 全域地形被策略改写（见红线 R5） | 负数无意义 |
| `debug` | 日志级别 | `0`-`3` | 超范围 → **JVM 中断**；`3` → 巨量日志（见红线 R3） | 4 档固定语义，越界是错误 |

JVM 参数覆盖：`-Dfarlands.<键>=<值>`。JVM 参数与文件同权，且不落盘。

## 3. 红线区

### R1：修改 `epoch_x` / `epoch_z`

禁止：手动修改已有世界的 `epoch_x` / `epoch_z`。

原因：所有已生成区块按旧原点存储。修改后引擎按新原点解释，**区块全部错位**。

验证：已测试（2026-09，跨世界残留事故复现了同类错位）。

处置：系统不阻止（无法区分"正确迁移"与"错误修改"）。优先使用 `/realtp` 或新建世界。

### R2：配置格式错误

禁止：写入非法值后启动。

原因：错误的 epoch 或 margin 会损毁世界；静默降级会把错误藏起来。

验证：已测试（`debug=5` → `POLICY VIOLATION` + JVM 中断）。

处置：`POLICY VIOLATION` → `Runtime.halt(1)`。**系统不会让你带着错误配置继续跑。**

### R3：`debug=3` 长期开启

禁止：`debug=3` 用于正常游玩。

原因：产生逐区块/逐 tick 追踪日志，磁盘与性能双重压力。

验证：已模拟（日志量推演：每区块数十行 × 视距区块数）。**未实测——按红线对待。**

处置：无（用户责任）。仅用于短时诊断。

### R4：现象区关闭流体限流

禁止：`fluid_tick_limit=0` 且处于异常地形（水柱世界）。

原因：每个流体方块触发递归坡度搜索；异常地形下流体 tick 数量激增，服务器线程持续 RUNNABLE 满载 CPU（Watchdog 已确认堆栈）。

验证：已测试（2026-09 压力测试：`Can't keep up! 95 ticks behind`，最终 AppHang）。

处置：无（用户责任）。保持默认 2000。

### R5：`worldgen` 参数实验

禁止：在含有不可替代存档的世界实验 `worldgen_*` 参数。

原因：采样策略改变会使新生成地形与旧地形不连续；`clamp`/`quantize` 产生重复/平坦地形；`worldgen_far_threshold=0` 使全域地形被改写。

验证：已测试（1e306，三模式生成正常、不崩）；**地形不连续未验证——按红线对待。**

处置：无（用户责任）。实验请在新建世界进行。

### R6：现象区长时间游玩

禁止：在现象区（2^53 以外）长时间游玩。

原因：现象区几何极重。32 视距下顶点数亿级（8GB 顶点缓冲），核显约 3fps；系统虚拟内存告急后主线程饿死（输入失效、渲染线程独立存活）。

验证：已测试（2026-09 压力测试：AppHangB1，任务管理器强杀）。

处置：无（用户责任）。短看/截图可以，长玩请 `/realtp` 回正常区域。

### R7：文档后果必须写实

禁止：后果描述使用超出实际现象的严重词（如"CPU 烧毁"）。

原因：过度的词会误导严重性判断，使真实红线贬值。后果是事实陈述，不是修辞。

验证：已修正（本文档，2026-09）。

处置：无（写作准则）。实际表述示例：CPU 持续满载 / 占用飙升 / 区块错位 / 数据错乱。

### R8：对待项目必须严谨严格

禁止：未验证下结论、跳过验证步骤、放松既有验证纪律。

原因：不严格会导致时间浪费与错误的实验结果。项目历史已多次验证此代价（无头 rig 与客户端差异导致多轮误判；未核对 jar 与 mod 的补丁集匹配导致双重转换事故）。

验证：项目历史教训（ROADMAP 五条铁律）。

处置：无（工作准则）。每次实验前写预期、实验后核对；构建失败禁止部署；每轮单变量；先验证代码真的在跑。

### R9：地形生成器深层调试域（噪声/密度函数级）

进入前提（全部满足才允许开始实验）：

1. **基线先行**：未修改状态先记录基线（固定种子、固定坐标集、版本标记、地形统计）。
2. **新世界**：只用新世界（R5），禁止在不可替代存档实验。
3. **单变量**：一次只改一个参数（R8）。
4. **预期先行**：每轮先写假设与预期，再跑实验。
5. **数据结论**：结论必须有测量数据（高度/方块统计/DF 输出/日志），禁止"看起来变了"。
6. **编号归档**：实验记录（编号、参数、种子、坐标、预期、实测、结论、文件）。

原因：噪声参数影响整条生成链路，肉眼不可靠；无基线无法判断变化；不严谨的实验产生错误结论并浪费时间。

验证：待执行（首次实验前建立基线流程）。

处置：无（工作准则）。违反任一条的实验结论一律作废。

## 4. 理由区

**为什么 epoch 要持久化，不能每次进世界重置？**
因为世界按 epoch 存储。重置会使远侧存档全部错位。持久化不是限制，是保护。

**为什么配置错误要中断 JVM，而不是用默认值继续？**
因为错误的 `epoch_x` 或 `relocate_margin` 会损毁世界。默认值会把错误藏起来，让你在几小时后发现存档已毁。中断是保护。

**为什么还开放这么多参数？**
因为你是硬核用户。参数开放 + 后果写明 + 红线验证 = 你可以在知情下自由实验。系统不替你决定，但也不纵容无知。

**为什么现象区不直接禁止进入？**
因为现象是项目目标本身。系统提供警告与守卫（流体限流），不提供禁令。

## 6. 自由区

你可以调：

- `auto_relocate`、`relocate_margin`、`relocate_discard_over`（重定位行为）
- `fluid_tick_limit`（性能取舍）
- `worldgen_*`（地形实验——在新建世界）
- `debug`（0-2 安全；3 见 R3）

调之前你需要知道：

- 每个参数的错误后果（见参数区）
- 哪些是红线（见红线区）
- 为什么（见理由区）

调烂了，炸了，是你的事。
系统不会让你带着错误配置继续跑。

## 7. 已知限制

- `> 1.8e308`：double 溢出 → 采样返回固定值（现象，非真实地形）
- 实体位置/渲染仍在 local 域（精度现象仅在地形采样层）
- 单机限定（联机需协议层纪元同步，未实现）
